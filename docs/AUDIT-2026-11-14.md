Scope: compare the stand-alone RAR Courier Suite 5.1.0 repository with the merged Pro 3.0.0 source and harden the existing Pro codebase without removing existing checkout, labels, manifests or reporting. Baseline commit: d79aa5ac510e9761d7c6153482ac84553e3927fd.

## Feature coverage and limitations

- Checkout: Bangladesh zone, area aliases, weight conversion, free shipping, ETA, rates, WooCommerce blocks and classic checkout remain based on existing Pro engine, without replacing working settings.
- API integrations ported from Suite: Pathao, RedX, SteadFast, Paperfly create/status modules; Sundarban remains manual CN entry; Pathao and SteadFast webhooks and periodic status polling are present in source.
- Logging, encrypted API secrets, per-order lock, COD/advance-payment handling, printable labels/manifests, CSV reports and customer tracking are present in source. Presence does not establish real account connectivity.
- No official production proof for Paperfly's community-SDK endpoints, some RedX status/area endpoints, or tracking templates. Verify with current merchant documentation and real provider credentials.
- There is no evidence available in this audit that API booking, checkout on the shop's active theme, HPOS on and off, or all provider callbacks have succeeded on a live WordPress instance. This is a release acceptance gap, **not** a passed test.
- Source-defined support is WordPress >=6.2, WooCommerce >=8.0, PHP >=7.4. Running PHP syntax/logic tests alone cannot certify the current/latest WooCommerce and WordPress release matrix.

## Minimum release acceptance checklist

- [ ] Full recoverable database backup and restore procedure rehearsed on staging
- [ ] Legacy Suite settings and Pro settings reconciled, no plaintext secrets in logs or screenshots
- [ ] Historic source parcel counts and sample consignment/status parity by courier and age
- [ ] Suite deactivated, Pro dispatch booted, only one Pathao/SteadFast webhook route active
- [ ] Pathao single and bulk booking once; verify second request blocked, inspect timed-out request on merchant panel
- [ ] Test RedX, SteadFast and Paperfly using merchant-approved endpoints and test orders; Sundarban manual CN/status
- [ ] Webhook authorization, duplicate/out-of-order delivery and terminal-state protections checked
- [ ] WP-Cron or server cron actually executes status sync; provider status matches board after refresh
- [ ] COD remaining vs prepaid and RAR Advance Payment totals reconciled for real orders
- [ ] Shipping fees/areas/weight/free shipping tested with classic and block checkout, including mobile
- [ ] Tracking page/My Account/email, PNG/PDF barcode labels and courier manifests inspected
- [ ] HPOS ON and legacy storage cases regression-tested
- [ ] Production cutover monitored before deleting Suite; delete-data-on-uninstall disabled

## Build reproducibility

The quality.yml CI workflow validates PHP 7.4, 8.2 and 8.3 syntax and the standalone logic/migration/backfill regression tests, checks JS syntax, builds a single-root WordPress plugin ZIP, verifies ZIP entries, and calculates SHA-256. Its release job publishes an archive only if the test and package jobs pass. The release remains subject to the live acceptance list above.

## Safety and rollback notes

Do not regenerate existing consignment IDs. Do not delete or reset order meta as a migration shortcut. Do not enable two dispatch owners at once; Suite pauses the embedded Pro dispatch until deactivated. Store all credentials in encrypted options or wp-config constants, never documentation or logs. API network errors may be uncertain rather than rejected; reconcile on the courier's portal before retrying.
